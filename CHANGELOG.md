# Changelog

All notable changes to this project are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- `AGENTS.md` with the project's code hygiene rules (H1–H15), definition of done and layout; `CLAUDE.md` imports it.
- `docs/dependencies.md` dependency register.
- `docs/reviews/architecture/doc.md`: architecture assessment, decisions D1–D32.
- `docs/workstreams.md`: work breakdown along S1–S7 with dependencies and parallelism.
- Project bootstrap: `pyproject.toml` (Python 3.12, uv, per-platform torch sources for linux x86_64 CUDA 12.8 and linux aarch64 CPU, `gpu` extra, `dev` group, ruff, mypy, pytest and import-linter configuration), `uv.lock`, `.gitignore`, `.env.example`, root `conftest.py` registering the `gpu` and `integration` markers.
- `banhammer.core`: `Verdict` scale V0–V3 with the valid verdict–severity grid (D7), `BanhammerError` and `SettingsError`, frozen settings models read from `params.yaml` by `ParamsFile` (a settings model that declares a default is rejected at class creation, and the seed is bounded to `0 <= seed < 2**63`), and the `Seeder` helper that seeds Python, NumPy, torch, CUDA and `DataLoader` workers and hands out independent named generator streams.
- `params.yaml` with the `core` section, and `dvc init` with an empty `dvc.yaml`.
- `tests/test_hygiene.py`: scans `src/`, `tests/`, `scripts/` and the root `conftest.py` for the H1 comment and string (and bytes) rules, `while True` (H4), the `Functional module:` line (H3) and cross-subpackage private imports in `src/` and in tests (H16), with its own tests on fixture snippets.
- import-linter contract that `core` imports from no other subpackage.
- `.pre-commit-config.yaml` (ruff, ruff-format, mypy, import-linter, detect-secrets with `.secrets.baseline`, nbstripout; hook repos pinned to commit SHAs) and the commit-msg hook `scripts/check_changelog_entry.py`, which rejects a commit touching `src/` without a `CHANGELOG.md` change unless it is typed refactor, test, style or chore (renames count both paths; an amend is checked against its newly staged files only).
- Docker on the GPU box (D3, D6, D27): `Dockerfile`, `.dockerignore`, `compose.yaml`, `docker/judge-proxy.conf` and `docs/docker.md`. The `judge` profile runs vLLM v0.34.0 with Qwen2.5-7B-Instruct-AWQ at a pinned revision, offline, on an internal network with `gateway_mode_ipv4: isolated` (Docker 28 or later), so the host cannot reach vLLM directly. An nginx proxy, started once the judge is healthy, publishes only `127.0.0.1:8000`, forwards only `/v1/*` and `/health` using the normalized URI, rejects ambiguous raw URIs (dot segments, percent escapes, double slashes) and unexpected `Host` headers. The `train` profile runs the `work` image (CUDA 12.8.1, uv 0.12.0, locked environment in `/opt/venv`) as the host user, with `.git` read-only and `.env` hidden. All services drop capabilities and set `no-new-privileges`.
- `params.yaml` `judge:` section. `tests/compose_files.py`, `tests/test_compose_params.py`, `tests/test_compose_hardening.py` and `tests/test_judge_proxy_conf.py` check `compose.yaml` against `params.yaml`, the hardening rules, and `docker/judge-proxy.conf` (Host allow-list, URI parts, raw-URI rejection).
- Dependencies `sentence-transformers`, `huggingface-hub`, `polars` and `pandera[polars]` (D14, D1, D28), recorded in `docs/dependencies.md`; `polars` and `pandera` are added ahead of use by the S1 and S2 workstreams so those branches do not both edit `uv.lock`. `uv.lock` still resolves for linux x86_64 and aarch64.
- `banhammer.core.union_find.UnionFind`: incremental union-find over plain `str` or plain `int` keys (one kind per instance; other key types raise `InvalidKeyError`), with path compression, union by size, `union_all`, `group_size`, `group_count`, and a group id that is the smallest member key, so the same edges in any order give the same ids (D13, D15).
- `banhammer.core.model_snapshot.download_snapshot`: the one safe path for Hugging Face downloads. It rejects a revision that is not a full commit hash, fetches only safetensors, JSON and text files at that commit, and fails with `ModelSnapshotError` if the snapshot holds any other file.
- `banhammer.embeddings` (new subpackage, imports only `core`; D13, D14, D15): the `Embedder` protocol, `EmbedderSettings` (the `embedder` section of `params.yaml`: LaBSE at a full commit hash, `batch_size`, `max_seq_length`; `EMBEDDER_SECTION`), `SentenceTransformerEmbedder` (loads the snapshot offline without remote code, returns L2-normalized float32 arrays; exported lazily, so importing the package does not import `sentence_transformers`), and `ExactNeighbourSearch` with `NeighbourPairs`: exact top-k neighbours by chunked matrix product on a given device, `between(queries, corpus)` and `within(embeddings)` (excluding the row itself), with an optional `min_score` floor; `NeighbourPairs.edges()` gives plain-int pairs for `UnionFind.union_all`. Ties at the k-th place are broken by the backend; callers needing exact-duplicate grouping hash-dedup first. Input must be finite, float32 and L2-normalized. Errors: `EmbeddingError`, `NeighbourSearchError`.
- import-linter contract extended: `core` at the bottom, then `embeddings`, then the pipeline subpackages.
- `tests/embedder_double.py`: `FakeEmbedder`, the embedder test double.

### Changed

- torch 2.11 to 2.15 (`torch>=2.15,<2.16`): the x86_64 build moves from the `cu128` to the `cu132` index (`pytorch-cu132` in `pyproject.toml`); the aarch64 CPU build is unchanged. CUDA now comes from PyPI packages (`cuda-toolkit`, `nvidia-*-cu13`), triton moves to 3.9. The `work` image base is `nvidia/cuda:13.2.1-cudnn-runtime-ubuntu24.04` (pinned by tag and digest) and the apt layer runs `apt-get upgrade -y`. `compose.yaml` reserves one GPU (`count: 1`) for `judge` and `work` instead of all, and `tests/test_compose_hardening.py` checks it. `docs/docker.md` records the host driver, the pins and how to rebuild the image; `docs/dependencies.md` records the advisory check of 2026-11-26.

### Security

- setuptools 81.0.0 to 84.2.1 (PYSEC-2026-3447, GHSA-xmj3-9gf7-h52w, fixed in 84.1.0): possible because torch 2.13 and later no longer pin `setuptools<82`.
- Accepted, no fix available: diskcache 5.6.3 (PYSEC-2026-2447, CVE-2025-69872), a pickle read from a local cache directory.
- torch CVE-2026-136426 to CVE-2026-136433 (ZDI-26-1052 to ZDI-26-1059) were rejected upstream as expected behaviour, so no fix will come. The risk is accepted permanently and enforced by banning the loaders involved (`torch.export.load`, `torch._inductor.aoti_load_package`, `torch.hub.load` and `torch.hub.load_state_dict_from_url`, `torch.distributed.checkpoint`, `torch.compiler.load_compiled_function` and related names) through ruff `TID251` banned-api in `pyproject.toml`, with `tests/test_banned_torch_loaders.py`. `torch.utils.model_zoo`, `torch.compiler.load_cache_artifacts` and `torch.package` are banned too; the hygiene test requires the literal `weights_only=True` on every `torch.load`; a `notebook-loader-ban` pre-commit hook applies the bans to notebooks. AGENTS.md H16 names them and sets the `torch>=2.15.0` floor for the `weights_only` rule (GHSA-v32g-mr63-3j83, fixed in 2.15.0).
- Host driver 580.159.03 was affected by NVIDIA bulletin 5861 (CVE-2026-47501) and was upgraded to 595.104.02 (`docs/docker.md`, "Host driver"); the `gpu`-marked `tests/test_nvidia_driver.py` fails on any driver below its branch's fixed release.
